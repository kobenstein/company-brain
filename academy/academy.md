# Academy — lernen, indem das Unternehmen entsteht

## Auftrag

Die Academy begleitet echte Entscheidungen, Marktversuche und den Aufbau eines einfach führbaren Unternehmens. Sie ist kein Kurskatalog zum Abarbeiten und kein Vorwand, Kundentests durch Infrastruktur zu ersetzen.

## Drei Ebenen

**Unternehmensarbeit:** Kunde, Angebot, Umsatz, Delivery, Lernen. **Fähigkeiten:** genau das Wissen lernen, das den nächsten Engpass löst. **Gedächtnis:** wichtige Erkenntnisse als kurze belegte Einträge sichern.

## Feste Lerntracks

| Track | Praktischer Output |
|---|---|
| Problem-/Kundenverständnis | Vergangene reale Probleme, Buyer, Budget und Datenzugang |
| Geschäftsmodell / Wirtschaftlichkeit | Preis-/Margen-/Kapazitätshypothese, Stop-Regel |
| Creative Systems | Wiederverwendbare Methoden, Beispiele, Qualitätsprüfung |
| Performance Marketing | Testdesign, Messlogik, Dateninterpretation und Kampagnengrenzen |
| [Sustainability/Impact Marketing](../knowledge/sustainability-marketing.md) | Acht praxisbezogene Module und Claims-/Wirkungskette |
| Sales / Content | Geprüfte Ansprache, tatsächliche Reaktionen, nächste Hypothese |
| Company OS / Agenten | Ein verlässlicher, berechtigter Ablauf statt Tool-Sammlung |
| Finance / Recht | Belegorganisation und fachlich geklärte Entscheidungen |
| Exit / Übertragbarkeit | System, das ohne Gründerwissen weiterbetrieben werden kann |

## Tageslogik

Ein wichtigstes Ergebnis, höchstens drei Prioritäten. Zu Beginn tatsächliche verfügbare Zeit und letzten Arbeitsstand verwenden, keine verpassten Tage rechnerisch nachholen. Lernressource nur wählen, wenn sie die aktuelle Arbeit verbessert. Tagesabschluss knapp: Was wirklich getan? Welche Belege? Was gelernt? Nächster Engpass?

## Jetzt, am 25.09.2026

**Tatsächlich begonnen:** Company-Brain-Neuaufbau mit Quellensuche und Git-Versionierung. **Nicht belegt:** Pilotverkauf, Outreach-Versand, absolvierte Kurse oder automatische produktive Integrationen.

Nach diesem Paket folgt sinnvollerweise ein schmaler Betriebtest: Brain in der gewünschten Oberfläche auffindbar machen, eine neue Idee und eine bestätigte Entscheidung kontrolliert speichern, danach auf den nächsten echten Kundenschritt wechseln. Kein vollständiger Tech-Stack als Voraussetzung.

## Review

Regelmäßig prüfen: Wichtigster Engpass, neue Kundenevidenz, tatsächliche Stunden/Kosten, Integrität, offene Entscheidungen. Ein Tagesplan ist kein erledigter Arbeitstag. Frühere Academy-Pläne, die noch Recommerce priorisieren, sind historisch und nicht automatisch der heutige Auftrag.
